# AI Manuscript Repair

这是一个绝望的文字编辑在和某些（明眼人都看得出来这就是deepseek写的）稿件斗智斗勇的过程中搓出的 Codex Skill。

区别于常规“去AI味”的 Humanizer，即“使文章更像人”的思路，它不负责增加“人味”，甚至并不专注常见 AI 模板句式如“不是……而是……”。相反，在人工判断“别想了，这就是deepseek写的”之后，它不再考虑 AI 味本身，只是将文字内容当作一份正常稿件，进行编辑加工，对语病进行最小化修改。

例如：

> 我们引以为傲的核心流程，在执行的最后一公里被野蛮地抄了近道。而我们寄予厚望的优秀员工，离职时带走的不仅仅是一个岗位编制，更是那些无法用文档量化的宝贵经验，让继任者在信息的废墟上艰难重建。

看似文学艺术，实则狗屁不通。人类一般不会写出这种东西交给编辑，但是编辑确实可以通过正常的编辑审校工作来处理这些问题——但看一整本书的这种东西也太工伤了，何况有时候明知道这句话不对，但具体哪里不对、怎么改也很成问题，所以有了这个 Skill。

它可以把上面那段话改成：

> 我们引以为傲的核心流程，其执行的最后一公里被粗暴地绕过。而我们寄予厚望的优秀员工，一旦离职，不仅会留下岗位空缺，还会造成那些未能通过文档沉淀的宝贵经验流失，迫使继任者在信息残缺的情况下艰难重建。

可以看出，它没有进行 Humanizer 上的去AI味，没有口语化、句式变化、个人感之类的东西，因为重写并不属于编辑加工的范畴。由此，它也就避免了 AI 在 Humanizer 时因为根本没有任何的人味，反而创造了新的 AI 味的弊病。

我发现这可以是去AI味的另一种思路：不要努力扮演人类，但是好好讲话。先不谈 AI 不 AI，就看这里有没有一个按照正常中文语法的标准，可以明确定位并局部修改掉的语言问题。

主要包括而不限于：

* 搭配不当；
* 施事、动作和受事错位；
* 指代或修饰关系不清；
* 混合比喻；
* 并列层级混乱；
* 连接关系不成立；
* 近义词和抽象名词堆叠；
* 机械重复和无意义强调；
* AI 生成措辞导致的论断强度失真；
* 其他能够在不改变作者意思的情况下局部解决的语言问题。

当然，AI味的构成远比狗屁不通更复杂，对于 GPT 这种本身语法还行的模型，其运用效果就会大打折扣。

## 输出

默认生成两个文件：

* `minimal-edits.pdf`  
  在原文位置加红色下划线，批注中写完整修改。

* `minimal-edits.md`  
  只保留三列：`页码 | 原句 | 修改`。

另外还有一个实验性的局部一致性功能，可以把同一对象前后称谓不稳定的位置标成黄色，例如同一个角色一会儿叫“采访者”，一会儿叫“专业采访者”，一会儿又变成“企业知识管理顾问”。

这个功能默认关闭，因为目前误报仍然比直接语言修复多。需要时可以显式开启，辅助处理局部一致性问题。

## 安装

需要 Python 3.12 或 3.13，以及已经登录的 Codex 环境。

```bash
python -m venv .venv
.venv/bin/python -m pip install -e '.[test]'
```

## 使用

直接处理整份 PDF：

```bash
.venv/bin/ai-manuscript-repair input.pdf --output-dir output
```

只测试部分页面：

```bash
.venv/bin/ai-manuscript-repair input.pdf --output-dir output --pages 19-23
```

开启实验性的黄色一致性标记：

```bash
.venv/bin/ai-manuscript-repair input.pdf --output-dir output --include-consistency
```

目前只支持**带可用文本层的横排中文 PDF**。扫描件、竖排和复杂多栏版面暂时不在支持范围内。

更完整的判断标准和输出约束见 [`SKILL.md`](SKILL.md)。
